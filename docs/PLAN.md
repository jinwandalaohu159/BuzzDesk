# PLAN

## 1. 目标边界

第一阶段目标是做出一个可真实使用的桌面替代层：启动后隐藏 Windows 原生桌面图标，只保留壁纸，并在壁纸上显示我们自己的图标层。

这个计划不把产品做成普通启动器，也不做多页桌面。核心体验集中在真实桌面图标、高级玻璃质感、横向网格布局、手机式虚拟文件夹，以及 120fps 以上体感的拖拽动画。

## 2. 优先级原则

先验证最容易翻车的系统边界，再打磨前端体验。

优先级顺序为：真实桌面识别、原生图标隐藏、真实图标扫描、高清图标显示、桌面层窗口行为、横向布局、拖拽整理、虚拟文件夹、展开面板、动画质感、性能验收。

所有阶段都要避免把组件展示、交互逻辑、布局计算和动画编排混在一起。

## 3. 阶段一：桌面接管验证

验证 App 能识别真正的 Windows 桌面，而不是当前窗口或普通全屏界面。

验证启动后可以隐藏原生桌面图标，并保留原本壁纸。

验证我们的桌面层能覆盖原生桌面图标，但不会永远压在普通应用窗口上方。

验收标准：启动 App 后用户看到的是壁纸加我们的图标层；打开其他应用后，应用窗口能正常显示在桌面之上。

## 4. 阶段二：桌面项目扫描

扫描 Windows 桌面上的所有项目，包括快捷方式、应用、文件、文件夹、回收站、此电脑等系统桌面项。

扫描结果要能用于展示、打开和虚拟分组。

不能只扫描用户桌面文件夹，也不能把当前屏幕内容当成桌面数据。

验收标准：真实桌面上能看到的主要项目，在我们的桌面中都能出现。

## 5. 阶段三：高清图标显示

所有桌面项目都使用系统或软件自带的真实图标。

图标需要有高清版本，不能出现明显模糊、低清、锯齿、默认占位图。

桌面大图标和文件夹封面里的小图标都从同一套高清图标缩放而来。

验收标准：常见软件图标、文件类型图标、文件夹图标、回收站和此电脑图标都清晰可辨。

## 6. 阶段四：横向桌面布局

实现单屏横向网格布局。

图标从左到右排列，排满一行后换到下一行。

不做多页桌面，收纳能力通过文件夹解决。

布局需要适配不同屏幕尺寸，避免图标、名称和文件夹面板超出屏幕。

验收标准：桌面项目按横向网格稳定排列，窗口尺寸或屏幕尺寸变化后仍然可用。

## 7. 阶段五：普通图标操作

普通图标支持选择、拖拽整理和双击打开。

双击图标后打开对应真实应用、文件、文件夹或系统项目。

拖拽过程中图标必须跟手，不能有明显延迟、跳动或卡顿。

验收标准：用户可以像使用桌面一样打开真实项目，也可以拖动图标进行整理。

## 8. 阶段六：虚拟文件夹创建

用户将一个图标拖到另一个图标上时显示合并预览，鼠标松开后形成虚拟文件夹。

形成文件夹时不移动、不修改、不重排真实 Windows 桌面上的文件或快捷方式。

合并过程需要有明确反馈，表现为靠近、吸附、缩小、收进圆角矩形。

验收标准：两个桌面图标可以通过拖拽预览并在松手后合成一个手机式虚拟文件夹，真实桌面文件不发生变化。

## 9. 阶段七：文件夹管理

用户可以继续把桌面图标拖入已有文件夹。

用户可以从文件夹中拖出图标。

文件夹剩余 1 个图标时，文件夹自动解散。

文件夹是虚拟分组，所有整理结果只影响我们的桌面状态。

验收标准：拖入、拖出、解散规则符合手机桌面文件夹心智，并且不会影响真实文件位置。

## 10. 阶段八：文件夹视觉

桌面文件夹使用手机式圆角矩形封面。

封面内部显示缩小后的 App 图标，不显示 App 名称。

文件夹下方显示文件夹名称。

文件夹容器比例和内部小图标尺寸需要作为可调整参数。

验收标准：文件夹看起来像高级手机桌面文件夹，而不是 Windows 普通文件夹。

## 11. 阶段九：文件夹展开与重命名

点击文件夹后，文件夹居中展开为浮层面板。

展开面板大小自动适配屏幕，不能超出屏幕边界。

文件夹名称显示在顶部，双击顶部名称进入重命名状态。

文件夹内图标可以双击打开真实应用或项目。

验收标准：文件夹展开稳定、清晰、可重命名，内部项目可正常打开。

## 12. 阶段十：高级玻璃质感

文件夹封面、文件夹展开面板、选中态、拖拽悬停态需要体现高级玻璃质感。

玻璃效果应表现为半透明、柔和高光、轻微描边、细腻阴影和适度层次。

不能为了玻璃质感牺牲文字可读性、图标清晰度和动画性能。

验收标准：在明亮和深色壁纸下，界面都清晰、克制、精致，不廉价、不厚重、不过度发光。

## 13. 阶段十一：动画系统

拖拽、合并预览、松手合并、重排、展开、收起都需要连续动画。

动画必须可打断。拖到目标上又移开时，预合并状态要自然回退。

重排不能瞬移，文件夹展开不能直接弹窗。

验收标准：主要交互看起来像系统级桌面体验，而不是网页控件拼接。

## 14. 阶段十二：120fps 体感优化

拖拽过程必须以 120fps 以上体感为目标。

拖拽中不能频繁触发大范围重绘、重新布局或图标重新解码。

高清图标需要提前准备和缓存，拖拽过程中不能临时生成或加载。

动画主要围绕位置、缩放、透明度等轻量变化完成。

验收标准：快速拖动、连续合并、展开关闭文件夹时，体感仍然顺滑，没有明显掉帧、卡顿或输入延迟。

## 15. 阶段十三：状态保存

虚拟文件夹、文件夹名称、图标排列结果需要持久化。

关闭 App 后再次启动，应恢复用户整理过的桌面状态。

真实 Windows 桌面文件不应因为状态保存而被移动或修改。

验收标准：重启 App 后，虚拟分组、文件夹名称和布局能恢复。

## 16. 阶段十四：可维护性整理

视觉组件只负责展示，不直接处理复杂业务规则。

交互逻辑单独管理，包括拖拽、合并预览、松手提交、拖入、拖出、双击打开、重命名。

布局逻辑单独管理，包括横向网格、文件夹内部排列、屏幕边界适配。

动画编排单独管理，避免散落在每个组件里。

验收标准：后续新增功能时，不需要在多个组件里到处改同一套交互规则。

## 17. 第一版完成标准

App 可以接管真实桌面图标层，并显示完整桌面项目。

所有主要图标清晰，桌面按横向网格排列。

用户可以双击打开真实项目。

用户可以拖拽创建虚拟文件夹、拖入文件夹、拖出文件夹，文件夹剩 1 个图标时自动解散。

文件夹可点击居中展开，可重命名，视觉具备高级玻璃质感。

拖拽、合并、展开、重排达到 120fps 以上体感目标。

组件展示、交互逻辑、布局逻辑、动画编排保持分离。
